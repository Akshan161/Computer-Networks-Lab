## 3. Theoretical Background

### What is the Domain Name System (DNS)?
DNS is an Application Layer protocol that translates human-friendly domain names (e.g., `www.google.com`) into machine-routable IP addresses (e.g., `142.251.155.119` or `2001:4860:482a:7700::`).

- **Transport Protocol:** DNS typically runs over **UDP Port 53** for standard queries and responses due to low latency. It uses **TCP Port 53** for zone transfers or responses exceeding 512 bytes (EDNS0 allows larger UDP payloads).
- **Hierarchical Namespace:** Root servers (`.`) $\rightarrow$ Top-Level Domain (TLD) servers (`.com`, `.org`) $\rightarrow$ Authoritative Name Servers.

### DNS Packet Structure & Key Fields:
1. **Transaction ID (16 bits):** An identifier assigned by the client program to match query requests with incoming server responses.
2. **Flags (16 bits):**
   - **QR (Query/Response Flag):** `0` = Query, `1` = Response.
   - **Opcode (4 bits):** Standard query (`0`), inverse query (`1`), or server status request (`2`).
   - **AA (Authoritative Answer):** Indicates whether the responding server is authoritative for the domain.
   - **TC (Truncated):** Indicates if the message exceeded the maximum permitted size.
   - **RD (Recursion Desired):** Set by client to request recursive resolution from the local resolver.
   - **RA (Recursion Available):** Set by server to denote recursion support.
   - **RCODE (Response Code):** `0` = No error, `3` = NXDOMAIN (Non-Existent Domain).
3. **Questions Section:** Contains the domain name queried, Query Type (e.g., `Type A` for IPv4, `AAAA` for IPv6, `MX` for Mail Server, `NS` for Name Server), and Query Class (`IN` for Internet).
4. **Answers Section:** Contains Resource Records (RR) returning resolved IP addresses, TTL (Time to Live in seconds), and data length.
5. **Authority & Additional Records:** Information on authoritative name servers and their corresponding glue records.

## 4. Step-by-Step Procedure

### Part A: Using DNS Commands (`nslookup`)

1. Open Command Prompt (`Win + R` $\rightarrow$ type `cmd` $\rightarrow$ press Enter).
2. **Forward DNS Lookup:**
   ```cmd
   nslookup www.google.com
   ```
   *Observe:* Local DNS Server used, Server IP, non-authoritative answer listing IPv4 and IPv6 addresses.
3. **Reverse DNS Lookup (IP $\rightarrow$ Domain):**
   ```cmd
   nslookup 142.251.155.119
   ```
   *Observe:* PTR query resolving IP to canonical host name.
4. **Query Mail Exchange (MX) Records:**
   ```cmd
   nslookup -query=MX google.com
   ```
   *Observe:* Mail server hostnames (`smtp.google.com`) and MX priority/preference values.

---

### Part B: DNS Packet Analysis with Wireshark

1. **Launch Wireshark:** Open Wireshark as Administrator.
2. **Select Active Interface:** Choose the active network adapter (e.g., `Wi-Fi` or `Ethernet`) and click the blue shark-fin button to start live capture.
3. **Generate DNS Traffic:** Open Command Prompt and execute:
   ```cmd
   nslookup www.google.com
   ```
4. **Stop Capture:** Click the red square icon in Wireshark.
5. **Apply Filter:** In the filter bar at the top, enter:
   ```wireshark
   dns
   ```
   Press Enter.
6. **Analyze Captured DNS Query:**
   - Locate the DNS Query packet from client IP to DNS Server IP (Destination Port 53).
   - Expand the **Domain Name System (query)** tree:
     - Note the **Transaction ID** (e.g., `0xb004` or `0xb879`).
     - Note the **Flags**: `Standard query (0x0100)`, `Recursion desired: True`.
     - Inspect the **Queries** item: `Name: www.google.com`, `Type: A (Host Address)`, `Class: IN`.
7. **Analyze Captured DNS Response:**
   - Locate the subsequent reply packet with matching Transaction ID.
   - Note the **Flags**: `Standard query response, No error (0x8180)`.
   - Inspect the **Answers** section: Note the resolved IPv4 addresses, data length (4 bytes), and TTL countdown value.
